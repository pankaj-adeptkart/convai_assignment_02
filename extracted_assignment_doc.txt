Dataset Specification
Dataset: Natural Questions (NQ) — Simplified Version
Source: https://huggingface.co/datasets/natural_questions  (alternative: SQuAD v2)
Size / Use: Use approximately 500–1,000 examples overall; use smaller controlled subsets for individual experiments.
Assignment Problem Statement
Build and evaluate an end-to-end research assistant that can reason over research questions, call multiple sources safely, use working and episodic memory, decompose and refine complex questions, engineer context, synthesize conflicting evidence, detect and correct hallucinations, calibrate confidence, and make evidence-based architecture/cost decisions.
Task 1: Multi-Step Reasoning Strategy Evaluation — 1.0 Marks
Objective: Determine which prompting strategy is most suitable for research questions of different complexity.
1. Research Questions
Create 10 questions: 3 simple, 3 medium, 2 complex, and 2 ambiguous/conflicting.
Use one research domain such as Science, History, Health, Technology, or Finance.
2. Prompting Techniques
Compare Zero-Shot, Few-Shot, Chain-of-Thought (CoT), Tree-of-Thought (ToT), and APE for Research.
For ToT, generate a small number of candidate reasoning paths and select the best-supported path.
3. Metrics
Measure reasoning correctness, a consistently defined reasoning-depth proxy, input/output tokens, latency, and estimated cost.
Use the same evaluation questions and criteria for all techniques.
4. Analysis
Include 2–3 visualizations, such as correctness vs. technique and reasoning depth vs. latency.
Discuss when a more elaborate reasoning strategy is justified by quality improvement.
Inference / Analysis Questions
Which technique is most reliable for complex questions?
How should strategy selection change with question complexity?
What is the quality–cost trade-off?
Task 2: Multi-Source Function Calling with Security & Safety — 1.5 Marks
Objective: Build a safe multi-source research agent using function calling/ReAct and parallel execution.
1. Tools and Schemas
Define at least 5 tools: academic search, Wikipedia search, news search, source-credibility checking, and citation generation.
Create JSON schemas with descriptions, required/optional fields, enums where applicable, and validation constraints.
2. Agent Execution
Implement the ReAct control loop: Rationale → Action → Observation → Loop Control.
Execute independent source calls in parallel and compare sequential vs. parallel latency.
3. Safety
Implement: iteration limits, repetition detection, tool-failure tracking, timeout protection, input validation, and graceful degradation.
Analyse prompt injection, unauthorized source access, data exfiltration, and indirect prompt injection.
4. Security Demonstration
Demonstrate at least one attack and the corresponding defence. Show that the defence blocks or safely contains the attack.
Run 3–5 complex multi-source research questions and report tool-call accuracy/task completion.
Inference / Analysis Questions
Which security risk is hardest to defend against?
How does parallel calling affect latency?
What trade-off exists between safety checks and execution cost?
Task 3: Agentic Memory, Query Decomposition, Iterative Refinement & Context Engineering — 1.5 Marks
Objective: Study how memory, decomposition, refinement and context engineering improve research assistance without repeating previously assessed retrieval techniques.
1. Working Memory
Implement bounded working memory with the last N=10 research steps, truncation, and a rolling summary.
2. Episodic Memory
Generate 20 clearly labelled synthetic research sessions.
Use a simple similarity/matching mechanism to identify relevant past sessions and demonstrate how memory changes an answer or workflow.
3. Semantic Knowledge
Use 10–15 curated or instructor-provided domain documents/snippets as evidence.
Do not implement BM25, Dense Retrieval/HNSW, or RRF in this task.
4. Query Decomposition & Refinement
For 5 complex questions, create 2–4 sub-queries using CoT or ToT.
Compare direct vs. decomposed answering and allow at most 2 refinement iterations.
5. Context Engineering & Ablation
Construct a final context containing system instructions, memory, evidence, history, query and tool definitions.
Show an actual token breakdown and classify context as task-relevant signal, potentially redundant context, or operational context.
Compare: query+system only; +memory; +engineered evidence/context. Report quality, token use, latency and cost.
Inference / Analysis Questions
How does memory help without becoming noise?
What is the marginal value of refinement?
If context must be reduced by 30%, what would you trim first and why?
Task 4: Multi-Source Synthesis, Conflict Resolution, Hallucination Detection & Confidence Calibration — 1.5 Marks
Objective: Synthesize supplied evidence, resolve conflicts, verify claims, and measure confidence calibration.
1. Evidence Assessment
For each evidence item, assess relevance, credibility/authority, and whether it directly supports the claim.
Evidence is supplied/curated; no BM25/Dense/HNSW/RRF implementation is required.
2. Conflict Resolution
Create 5 conflict scenarios and implement one strategy: majority vote, credibility-weighted decision, or evidence-strength scoring.
Report conflict-resolution rate and show at least one case where the final answer changes after conflict resolution.
3. Citation & Hallucination Control
Generate citations for claims and measure citation accuracy.
Run a verification pass; flag unsupported claims and regenerate using only supported evidence.
Compare hallucination rate before and after self-correction.
4. Confidence Calibration
Assign claim-level confidence in [0,1] and compute Expected Calibration Error (ECE).
Use 5 held-out questions for a compact RAG Triad evaluation: Context Relevance, Groundedness, Answer Relevance, using an anchored 1–5 rubric.
Inference / Analysis Questions
What causes conflicts between sources?
Does self-correction justify its extra latency?
Is the system overconfident or underconfident?
Which RAG Triad stage fails most often?
Task 5: Instruction Tuning & Alignment Analysis — 1.0 Marks
Objective: Understand Self-Instruct and alignment concepts through a compact analytical implementation.
1. Self-Instruct
Create 5 seed research tasks and generate 30 synthetic instructions/input-output examples.
Filter duplicates/low-quality examples and report the final dataset size and quality distribution.
2. DPO
Calculate a DPO loss for one supplied preferred/rejected pair, showing likelihood ratios, log ratios, sigmoid and final loss.
3. PEFT & Alignment
Compare Full Fine-Tuning, LoRA and QLoRA conceptually on trainable parameters, memory, storage, forgetting risk and use case.
Briefly compare PPO and GRPO and discuss one or two advanced alignment methods covered in the course.
Inference / Analysis Questions
What are the risks of self-generated training data?
Why is DPO attractive compared with reward-model-based RLHF?
Why is QLoRA resource-efficient?
Task 6: Paradigm Differentiation & Multi-Turn Research — 1.5 Marks
Objective: Differentiate Prompting, RAG and Fine-Tuning and test the assistant's ability to retain context across turns.
1. Paradigm Comparison
Compare Prompting, RAG and Fine-Tuning using research-specific criteria: knowledge freshness, controllability, cost, latency, hallucination risk and maintenance.
Run 5 questions through Zero-Shot, evidence-grounded RAG, and a simulated fine-tuning condition; report quality, hallucination rate, latency and cost.
2. Decision Framework
Create a decision tree for selecting Prompting, RAG or Fine-Tuning for a new research task.
Explain a hybrid RAG + Fine-Tuning scenario.
3. Multi-Turn Conversation
Simulate a 4-turn research conversation with follow-up clarification, criticism and comparison.
Measure Context Retention Score (1–5) and Follow-up Accuracy (1–5).
Inference / Analysis Questions
When is RAG preferable to fine-tuning?
What information should persist across turns?
How does multi-turn research differ from single-turn Q&A?
Task 7: Full Research Assistant Integration, Evaluation & Cost Recommendation — 2.0 Marks
Objective: Integrate the revised Tasks 1–6 into a compact end-to-end research assistant and make an evidence-based production recommendation.
1. Integration
Build a ResearchAssistant class combining the selected reasoning strategy, ReAct/tools, memory/context, evidence synthesis, verification and confidence handling.
Reuse task components rather than rebuilding them.
2. End-to-End Evaluation
Evaluate 10 held-out research questions across simple/complex/ambiguous cases.
Report synthesis quality, citation accuracy, hallucination rate, task completion, latency and cost.
Identify 2 failure cases and perform root-cause analysis.
3. Lightweight Audit Trail
For one complex query, record the original question, sub-queries, tool calls, evidence, claims, confidence and final synthesis in a structured JSON audit record.
Report claim-to-source traceability.
4. Production Recommendation
Provide one architecture diagram and an architecture decision table covering prompting, memory, evidence handling, verification and model choice.
Calculate approximate cost per query and propose two cost-reduction strategies.
Provide 2–3 visualizations and a final recommendation supported by experimental evidence.
Inference / Analysis Questions
What is the most critical component for synthesis quality?
What would you fix first before production?
Which optimization gives the best quality–cost trade-off?
